# AGENTS.md — Magnhild Myskja Portfolio

Minimalist one-page portfolio + CV for Magnhild Myskja, a communication professional looking for work
in Norway. **All user-facing copy is Norwegian**; code identifiers are English. `README.md` is the
front door for humans — this file is for how to work in the repo.

**Live URL**: https://magnhildmyskja.no

## Stack

React 19 + TypeScript (`strict`), Vite 7, **Tailwind CSS v4** via the `@tailwindcss/vite` plugin (no
`tailwind.config.js` — the theme lives in `@theme` inside `src/index.css`), **TanStack Router**
(file-based, code-generated), Framer Motion. `<head>` tags (`SEO.tsx`) rely on React 19's native
hoisting of `<title>`/`<meta>`/`<link>` rendered anywhere in the tree — no provider, no dependency.
Vitest + Testing Library + jsdom. pnpm, pinned via `packageManager` in `package.json`.

Hosting is **GitHub Pages**, built and deployed by Actions — not a server. `base: '/'` in
`vite.config.ts` because the site is on a custom domain (`public/CNAME`), not a project subpath.

## Commands

This repo is pnpm-pinned. Do not use `npm`.

```bash
pnpm dev             # Vite dev server
pnpm build           # tsc -b && vite build && node scripts/prerender-routes.mjs  → dist/
pnpm preview         # serve the production build
pnpm lint            # eslint . --max-warnings=0
pnpm types:check     # tsc -b
pnpm prettier        # write
pnpm prettier:check  # verify (what CI runs)
pnpm test            # vitest, watch
pnpm test:run        # vitest, single run (what CI runs)
```

## CI/CD

- **`.github/workflows/ci.yml`** runs on **pull requests only**: lint → types:check → prettier:check →
  tests (with coverage) → build. `main` is protected and requires this check, which is why the workflow
  has no `push` trigger — the merge itself is the gate.
- **`.github/workflows/deploy.yml`** runs on push to `main` (and `workflow_dispatch`): builds and
  publishes `dist/` to GitHub Pages. The custom domain and its HTTPS cert are GitHub Pages settings
  plus `public/CNAME` — a build that loses `CNAME` takes the domain down.
- Both workflows use `corepack enable` (pnpm version comes from `packageManager`) and
  `node-version-file: .node-version`. Don't hardcode a pnpm or Node version in a workflow.
- **You cannot push to `main`.** Branch → PR → merge once CI is green.

## CV data model — `src/data/cv.ts`

Three exported arrays, three interfaces. Optional fields are genuinely optional and render
conditionally; omit them rather than writing empty strings.

```ts
Experience { title, company, period, type?, description? }   // type: 'Heltid' | 'Deltid' | 'Prosjektbasert'
Education  { institution, degree, period, details? }
Volunteer  { organization, role, period }                    // no optional fields
```

**`period` is an opaque Norwegian display string**, and the convention differs per array — match the
neighbours rather than inventing a format:

- `experience` uses month precision: `'nov. 2023 - Nå'`, `'aug. 2021 - jan. 2023'`. Ongoing is **`Nå`**.
- `education` and `volunteer` use years only: `'2023 - d.d.'`, `'2022 - 2023'`, `'2013'`. Ongoing is
  **`d.d.`**.
- Norwegian month abbreviations: `jan. feb. mar. apr. mai jun. jul. aug. sep. okt. nov. des.` — note
  `mai` takes no trailing period, every other month does.

**Array order is render order.** Nothing sorts at runtime and nothing validates it — the arrays are
reverse-chronological by _start_ date, ongoing entries first. Inserting in the right position is the
whole job. The `update-cv` skill covers this workflow.

## Design guidelines

The visual design is settled. Fix bugs and accessibility within it; do not redesign it.

Theme tokens live in `@theme` in `src/index.css` — use the Tailwind classes they generate
(`bg-surface`, `text-primary`), never raw hex:

| Token               | Value     | Use                  |
| ------------------- | --------- | -------------------- |
| `--color-primary`   | `#1a1a1a` | text, borders        |
| `--color-secondary` | `#5f6773` | muted/secondary text |
| `--color-accent`    | `#3b82f6` | links, focus-visible |
| `--color-surface`   | `#f9f5f4` | page background      |

`--color-secondary` is tuned to just clear WCAG AA (4.5:1) on `--color-surface` — don't lighten it back
towards the original `#6b7280` (4.47:1, a fail) without re-checking contrast.

Typography is two Adobe Fonts families loaded in `index.html`: `--font-serif` (`kepler-std`) for every
heading via the `h1–h6` base rule and `.font-serif-title`, `--font-sans`
(`neue-haas-grotesk-display`) for body at weight 200. Headings are deliberately **light** (weight 100)
— don't bolden them to "fix" hierarchy.

- Animations: subtle fade-in / slide-up only, and always from `src/lib/animations.ts`
  (`fadeIn`, `fadeInUp`, `fadeInUpLarge`, `defaultTransition`). Don't inline new variants.
  `MotionConfig reducedMotion="user"` wraps the app in `main.tsx`, so every `motion.*` element
  already respects `prefers-reduced-motion` — no per-component opt-in needed.
- The home page is scroll-snapped (`scroll-snap-type: y proximity` on `html`, `.section-full` +
  `scroll-snap-align: start`, `min-height: 100svh`). It was `mandatory` + `100dvh` originally; both
  were switched to fix a real bug where WebKit re-snaps mid-scroll and Safari's dynamic toolbar moves
  `dvh` targets during the animation, together sometimes preventing a hash-link scroll from landing.
  `scroll-padding-top: 4rem` on `html` offsets for the fixed header. A home section that isn't
  full-height still breaks the snap.
- Tailwind utilities for everything; custom CSS only in `index.css`'s `@layer components`.

## Adding a new page

1. Create a file in `src/routes/` (e.g. `prosjekter.tsx`) exporting a `createFileRoute` route.
2. The route is registered automatically — `routeTree.gen.ts` regenerates on the next `pnpm dev`/build.
   Commit the regenerated file; don't edit it.
3. Add the link to `NAV_LINKS` in `src/constants/navigation.ts` (and `ROUTES` if it's a real path,
   not a hash), and page metadata to `PAGE_META` in `src/constants/seo.ts`.
4. Render `<SEO title description canonical />` in the page, as `cv.tsx` does.

## Gotchas

- **`src/routeTree.gen.ts` is generated.** Never hand-edit. It is excluded from Prettier
  (`*.gen.*` in `.prettierignore`) and from coverage.
- **`public/CNAME` is load-bearing.** It's what keeps magnhildmyskja.no pointing at the Pages build.
- **`public/404.html`** exists so GitHub Pages doesn't 404 on a deep link into any _unregistered_
  path. `/cv` itself no longer depends on it — `scripts/prerender-routes.mjs` (run as part of
  `pnpm build`) writes a real `dist/cv/index.html`, so GitHub Pages serves it directly with a 200.
  Adding another top-level route needs an entry in that script's `ROUTES` map too, or it'll 404 on a
  hard refresh / to crawlers even though the SPA renders it fine client-side.
- **`public/og-image.jpg`** is generated from `mlm-profile.jpg`, not hand-authored — regenerate with
  `magick mlm-profile.jpg -resize 630x630 -gravity center -background '#f9f5f4' -extent 1200x630
-quality 88 og-image.jpg` (run from `public/`) if the photo changes.
- **CV list keys.** The `.map()`s in the CV sections key on `company` / `institution` / `organization`
  **plus `period`**, because a bare name is not unique — `education` already has two entries at Norges
  idrettshøgskole. If you add a list, key the same way.
- **The `@/` alias is declared twice** (`vite.config.ts` and `vitest.config.ts`). Change one, change both.

## Testing

`pnpm test:run` — Vitest + jsdom, setup in `src/__tests__/setup.ts`, coverage via v8 excluding
`routeTree.gen.ts`. Current suite covers `SkipLink`, `SEO` and `useReducedMotion` (component/hook
smoke tests) plus `spaRedirect` (pure-function table tests for the GitHub Pages redirect decoder).
There is **no E2E framework** — don't assume one exists or add one unprompted.
